## Kira Platform — Shell Concept (Otto, 23:00 CET)
Otto introduced the "shell" idea: always maintain a lighter multi-tenancy version of our advanced Kira setup that's public-facing. So the full Kira (what we run internally) is the advanced version, and there's always a stripped-down "shell" that external users can access. Key insight: we don't build a separate product — we maintain a public layer of what we already have. Every improvement we make internally can trickle down to the shell version. Multi-tenancy from day one.

## Kira Dashboard Architecture (23:30 CET)
Otto clarified the vision: Mission Control becomes the Kira Dashboard (web UI), Paperclip as company engine underneath. Key insight: ~/kira/app/ ALREADY has 80% of this built — task extraction, orchestrator, classifier, board view, today view, chat, agent monitor, XP, memory, NLP pipeline, gateway bridge. 30+ DB tables in PostgreSQL.

## Kira Platform Architecture Decisions (consolidated)
- **Three-layer stack:** Mission Control (forked, UI) → Paperclip (headless company engine) → OpenClaw (agent runtime)
- Paperclip's own React UI gets thrown away — only backend + DB kept
- Each Oopuo portfolio company = one Paperclip "company" (IAM, ZenithCred, Omiximo, etc.)
- Each Shell tenant = also a Paperclip company — dynamic, self-serve creation, not hardcoded
- Paperclip works with Claude Max: `claude_local` adapter spawns CLI binary which uses OAuth
- Otto monitors Paperclip activity through Kira Dashboard panels: Agent Monitor, Cost Dashboard, Task Board, Company Switcher, Activity Log, Heartbeat Monitor
- One unified UI — user never sees Paperclip or OpenClaw directly
