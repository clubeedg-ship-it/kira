# FIX-006 — Missing user_id Filter in Dependency Unblock

## Agent Instructions

Fix a **cross-tenant data leak** where dependency resolution can reference tasks from other users.

**Read:** `CRITICAL-FIXES.md` Section FIX-006, `src/server/engine/cascade.ts` lines 160-180

**What to do:**

1. **Find `tryUnblockDependents`** in `cascade.ts` (around line 140-180)

2. **Audit every query** in this function. Look for any `JOIN` on the `tasks` table that doesn't include `eq(tasks.userId, userId)`. The typical pattern to fix:

**Before (vulnerable):**
```typescript
const blockerStatuses = await db
  .select({ status: tasks.status })
  .from(dependencies)
  .innerJoin(tasks, eq(tasks.id, dependencies.blockerId))
  .where(eq(dependencies.blockedId, blockedTaskId));
```

**After (fixed):**
```typescript
const blockerStatuses = await db
  .select({ status: tasks.status })
  .from(dependencies)
  .innerJoin(tasks, and(
    eq(tasks.id, dependencies.blockerId),
    eq(tasks.userId, userId)
  ))
  .where(and(
    eq(dependencies.userId, userId),
    eq(dependencies.blockedId, blockedTaskId),
  ));
```

3. **Audit ALL dependency-related queries** across the entire codebase. Search for:
```bash
grep -rn "dependencies" src/server/ --include="*.ts" | grep -v node_modules
```
Ensure every query that touches dependencies AND joins to tasks/projects includes `userId` filtering on BOTH tables.

4. **Also check `src/server/routes/dependencies.ts`** — ensure list/create/delete all filter by userId.

5. **Add a comment** on each fixed query: `// FIX-006: explicit user_id filter prevents cross-tenant leak`
