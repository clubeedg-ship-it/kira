# FIX-002 — Race Condition in Cascade Logic

## Agent Instructions

You are fixing a **CRITICAL DATA INTEGRITY BUG**: concurrent task completions can corrupt milestone/project state because cascade logic runs without transactions or row locks.

**Read these files first:**
1. `CRITICAL-FIXES.md` — Section FIX-002
2. `src/server/engine/cascade.ts` — the entire file (290 lines)
3. `src/db/index.ts` — Drizzle DB connection (check if transactions are supported)
4. `src/server/engine/state-machine.ts` — state transitions that trigger cascades

**The problem:**
`onTaskComplete()` does: read task → check sibling tasks → update milestone → update project. These are separate queries with no transaction boundary. Two tasks completing simultaneously for the same milestone can both see "1 task remaining" and both mark the milestone complete — or interleave in worse ways.

**What to do:**

1. **Wrap `onTaskComplete` in a transaction:**
```typescript
export async function onTaskComplete(userId: string, taskId: string): Promise<void> {
  await db.transaction(async (tx) => {
    // ALL reads and writes inside here use `tx` instead of `db`
    const [taskRow] = await tx
      .select(...)
      .from(tasks)
      .where(...);
    // ... rest of function
  });
}
```

2. **Add row-level locking** where needed:
```typescript
// Lock the task row to prevent concurrent cascade
await tx.execute(sql`SELECT id FROM ${tasks} WHERE id = ${taskId} AND user_id = ${userId} FOR UPDATE`);
```

3. **Apply the same pattern to these functions:**
   - `onTaskComplete` — lock the task, then milestone if exists
   - `onProjectStatusChange` — lock the project row
   - `tryUnblockDependents` — lock the blocked task row before status change
   - `onMilestoneComplete` (if exists) — lock the milestone

4. **Replace all `db.` with `tx.` inside transaction blocks.** Functions that call other functions should pass the transaction handle:
```typescript
async function onTaskComplete(userId: string, taskId: string, txOrDb = db) {
  // use txOrDb everywhere
}
// When called from within a transaction:
await onTaskComplete(userId, taskId, tx);
```

5. **Handle deadlocks gracefully:** PostgreSQL will detect deadlocks and abort one transaction. Catch and retry:
```typescript
const MAX_RETRIES = 3;
for (let i = 0; i < MAX_RETRIES; i++) {
  try {
    await db.transaction(async (tx) => { ... });
    break;
  } catch (err) {
    if (err.code === '40P01' && i < MAX_RETRIES - 1) continue; // deadlock, retry
    throw err;
  }
}
```

**Rules:**
- Every function in cascade.ts that writes to DB must be inside a transaction
- Locking order: always lock parent before child (task → milestone → project → objective) to prevent deadlocks
- Don't lock more rows than needed — only the rows being read-then-written
