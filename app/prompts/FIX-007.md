# FIX-007 — Agent Work Fallback Mode Error Masking

## Agent Instructions

Fix dev-mode fallback that silently generates fake AI output, masking real failures.

**Read:** `CRITICAL-FIXES.md` Section FIX-007, `src/server/jobs/agent-work.ts` lines 240-268

**What to do:**

1. **Find the fallback block** — the code that checks `if (!ANTHROPIC_API_KEY)` and generates placeholder output

2. **Split behavior by environment:**

```typescript
if (!process.env.ANTHROPIC_API_KEY) {
  if (process.env.NODE_ENV === 'production') {
    throw new Error('ANTHROPIC_API_KEY is not configured. Cannot run agent work in production without it.');
  }
  
  // Development fallback
  console.warn(`[agent-work] ⚠️ FALLBACK MODE: No API key. Generating placeholder for task "${params.taskTitle}"`);
  
  return {
    text: `[FALLBACK — No API Key]\n\nThis is a placeholder result for: ${params.taskTitle}\n\nSet ANTHROPIC_API_KEY to enable real AI execution.`,
    tokensUsed: 0,
    costUsd: 0,
    model: resolvedModel,
    isFallback: true,  // ADD THIS FLAG
  };
}
```

3. **Propagate the `isFallback` flag** through the call chain:
- Add it to the return type of `callAnthropicAPI` (or whatever the function is named)
- Include it in the `agent_work_log` entry: either as a column or in the `details` JSON field
- Include it in the SSE event (`agent.work_completed` should have `fallback: true`)

4. **In the work log insertion**, mark fallback entries:
```typescript
await db.insert(agentWorkLog).values({
  // ... existing fields
  details: JSON.stringify({ fallback: output.isFallback || false, ... }),
});
```

5. **Optional but nice**: Add a startup warning when running without API key:
```typescript
// In worker.ts startup:
if (!process.env.ANTHROPIC_API_KEY) {
  console.warn('⚠️  ANTHROPIC_API_KEY not set. Agent work will use fallback mode (dev only).');
}
```
