# Oopuo Site Standard (OSS) — Website Template Specification

*Created: 2026-03-14*
*Status: Approved by Otto*

---

## Purpose

Every website built through the Oopuo Ops Platform must follow this standard. This ensures:
- The visual editor can parse, render, and modify any site
- Consistent quality across all client sites
- i18n, SEO, accessibility, and blogging work out of the box

---

## File Structure

Every site MUST follow this structure:

```
site/
├── pages/
│   ├── index.html          # Homepage
│   ├── about.html          # About
│   ├── contact.html        # Contact (with form)
│   ├── services.html       # Services/products
│   └── [custom].html       # Any additional pages
├── blog/
│   ├── index.html          # Blog listing (auto-generated by platform)
│   └── posts/
│       └── [slug].html     # Individual posts (auto-generated by platform)
├── assets/
│   ├── images/             # Uploaded media
│   ├── fonts/              # Custom fonts if any
│   └── favicon.svg
├── css/
│   ├── theme.css           # Design tokens (colors, fonts, spacing)
│   └── main.css            # Styles
├── js/
│   ├── i18n.js             # Internationalization
│   └── main.js             # Interactions
├── site.json               # Site manifest (metadata, nav, i18n config, SEO defaults)
└── theme.json              # Design tokens as JSON (editor reads this)
```

## site.json — Site Manifest

The platform reads this file to understand the site's configuration.

```json
{
  "name": "Client Name",
  "domain": "client.com",
  "defaultLang": "en",
  "languages": ["en", "nl", "de"],
  "nav": [
    {"label": "Home", "page": "index", "i18n": {"nl": "Home", "de": "Startseite"}},
    {"label": "About", "page": "about"},
    {"label": "Blog", "page": "blog/index"},
    {"label": "Contact", "page": "contact"}
  ],
  "seo": {
    "titleTemplate": "%s | Client Name",
    "defaultDescription": "...",
    "ogImage": "assets/images/og-default.jpg"
  },
  "analytics": {"enabled": true},
  "forms": [
    {"id": "contact", "page": "contact", "fields": ["name", "email", "message"]}
  ]
}
```

## HTML Conventions

The editor identifies editable content via `data-*` attributes. Every site MUST use these:

### Block-level attributes

```html
<!-- Every section gets a block type -->
<section data-block="hero" data-editable>
  <h1 data-field="heading" data-i18n="hero.title">Welcome</h1>
  <p data-field="subheading" data-i18n="hero.subtitle">We build things</p>
  <a data-field="cta" data-i18n="hero.cta" href="/contact">Get Started</a>
</section>
```

### Repeatable items

```html
<!-- Items that can be added/removed/reordered -->
<section data-block="features" data-editable data-repeatable>
  <div data-item>
    <h3 data-field="title">Feature 1</h3>
    <p data-field="description">Description</p>
  </div>
  <div data-item>
    <h3 data-field="title">Feature 2</h3>
    <p data-field="description">Description</p>
  </div>
</section>
```

### Attribute reference

| Attribute | Purpose |
|-----------|---------|
| `data-block="type"` | Identifies section type (hero, features, pricing, etc.) |
| `data-editable` | Marks section as editable in the visual editor |
| `data-field="name"` | Identifies specific editable field within a block |
| `data-i18n="key"` | i18n translation key — editor shows translation fields for all configured languages |
| `data-repeatable` | Items within can be added, removed, reordered |
| `data-item` | Individual item within a repeatable block |

## Built-in Block Types

Every template ships with these block types. The editor recognizes them and provides appropriate editing UI.

| Block Type | Description |
|------------|-------------|
| `hero` | Heading + subtitle + CTA buttons |
| `features` | Grid of feature cards (repeatable) |
| `services` | Services or pricing cards (repeatable) |
| `testimonials` | Client quotes (repeatable) |
| `team` | Team member cards (repeatable) |
| `contact-form` | Contact form wired to Forms & Leads module |
| `stats` | Numbers/statistics row (repeatable) |
| `faq` | FAQ accordion (repeatable) |
| `blog-latest` | Latest blog posts (auto-populated from blog module) |
| `footer` | Footer with links, social icons, legal text |
| `marquee` | Scrolling logo/partner bar (repeatable) |
| `two-column` | Text + image side by side |
| `cta-banner` | Call-to-action banner section |

## Quality Standards

Every site built on the platform automatically gets:

- ✅ **i18n ready** — all visible text through `data-i18n` translation keys
- ✅ **SEO** — meta tags, Open Graph, structured data (JSON-LD)
- ✅ **Mobile responsive** — works on all screen sizes
- ✅ **Accessibility** — semantic HTML, alt texts, ARIA labels, keyboard navigation
- ✅ **Performance** — static files, optimized/compressed images
- ✅ **Blog section** with RSS feed
- ✅ **Contact form** wired to Forms & Leads module
- ✅ **Cookie consent** (GDPR compliant)
- ✅ **Analytics snippet** (privacy-first, server-side via Umami)
- ✅ **Dark/light theme support** via theme.json

---

## CSS Rules

- **No inline styles** on HTML elements — all styling through CSS classes
- Design tokens from `theme.json` mapped to CSS custom properties in `theme.css`
- `main.css` references tokens via `var(--token-name)`
- Mobile-first responsive design
- Max-width container: defined in theme.json

---

## What the Platform Does Automatically

When a site follows this standard, the platform provides:

1. **Visual editing** — click any `data-editable` element to modify
2. **i18n management** — edit translations for all languages in one UI
3. **Blog generation** — posts created in the blog module auto-generate into `blog/`
4. **Form handling** — `data-block="contact-form"` submissions route to Forms & Leads
5. **SEO management** — edit meta/OG per page from the dashboard
6. **Theme customization** — modify `theme.json` values through a visual theme picker
7. **Publishing** — draft → review → publish workflow with version snapshots
8. **Analytics** — Umami snippet auto-injected
